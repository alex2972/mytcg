# Joey PC -> Godot 4 rebuild: plan

## Goal
Players should experience the same game (rules, card behavior, screens, flow, sounds, feel).
The code is NOT a port. The original (decompiled, `Z:\process\analysis\decomp.c`) is the *specification*,
not a template. We rebuild the systems in the simplest way that gives identical player-visible behavior.

## Principles
1. **Behavior is the contract.** Anything a player can see/hear/decide must match the original. Internals are free.
2. **Rules core is pure.** `core/` has no Nodes/scenes: it is plain GDScript (RefCounted) so it can be tested headless
   and later swapped (C#/Rust) if ever needed. UI only renders core state and sends choices back.
3. **Data over code.** The original hardcodes each card effect in giant per-ID switch statements. We classify all
   effects into a few reusable building blocks (trigger + condition + target + action) and describe each card in data.
   Odd one-offs get small handler functions registered by card id.
4. **Verify against the original.** For every milestone: write down the original's behavior (from decomp + running
   `joey_pc.exe`), encode it as headless tests/scenarios, and compare. Never "improve" a rule without a test showing
   the player-visible result is unchanged.
5. **Optimization is allowed only after parity.** Merge duplicates, shrink assets (BMP -> PNG/WebP, WAV -> OGG),
   data-drive things, but keep a parity test for each.
6. **Everything generated is reproducible.** `tools/` rebuilds `data/` and `assets/` from the original files.
   Original/extracted files are never committed or modified.

## Layout
```
godot-remake/
  core/        pure rules: card_db.gd, duel_state.gd, duel.gd, phases, battle, chain, effects/, ai/
  ui/          scenes+scripts: card_browser, duel_board, deck_editor, title, dialogs
  autoload/    Game (settings, language), Audio, CardDB singleton
  data/        generated: cards.json, strings.json, layouts (from original j/*.txt as needed)
  assets/      generated: cards/ mini/ ui/ voice/ (png/ogg when converted)
  tools/       python: unpack_dat.py, build_data.py, build_assets.py
  tests/       headless GDScript tests + scenario files
  docs/        PLAN.md, FORMATS.md (reverse-engineered formats), RULES.md (observed rules)
```

## Milestones
| # | Milestone | Done when |
|---|-----------|-----------|
| M0 | Data + asset pipeline | cards.json (1115 cards x 6 langs, stats decoded) + card art as PNG generated by tools |
| M1 | Card browser | Godot scene lists/filter/search every card with art; you verify against the original deck editor |
| M2 | Deck editor + files | Load/save `.ydc` decks, deck rules (40-60 cards, copy limits, ban list), card filters, `system.dat` settings |
| M3 | Duel core (no effects) | Headless duel: shuffle/draw, phases, normal summon/set/tributes, attack/battle math, positions, LP, win/lose, exodia |
| M4 | Duel board UI | Playable vs. a dummy opponent: field art, card movement, battle/summon animations, LP bar, dialogs, cursor, SFX |
| M5 | Effects | Catalogue all effect ids -> building blocks; chain system; spells/traps/flip/continuous/equip/fusion/ritual in batches, each with scenario tests |
| M6 | AI | Opponent AI matched to original behavior (summon/attack/spell decisions) |
| M7 | Game flow | Title, options, janken/coin, opponent select, win/lose screens, replays, tutorial, languages, voices, ending |
| M8 | Polish + slim down | Asset conversion, merge duplicates, packaging/export |
