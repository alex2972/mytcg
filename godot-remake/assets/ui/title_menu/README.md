# Main-menu additions

`options_gear.png` is used by the top-left Options button. It was generated with the built-in image generation tool; `source_sheet.png` preserves that source. The generated `plank_brown.png` and `plank_yellow.png` are retained as earlier artwork but are no longer used: their colors and static wood did not match the original menus.

SHOP and BACK use the original brown/yellow artwork in `assets/j/title/`. `ui/plank_art.gd` recovers the wood from matching pixels in the five localized idle atlases, using rows 0, 3, and 4, which share the same underlying grain. White labels brighten brown wood, while dark labels darken yellow wood; comparing their copies exposes the original background. The result retains the wood at its native pixel coordinates, including its edges and bevel. It is cached in memory. No inset rectangles, mirrored tiles, stretched strips, or generated wood are used.

The labels use Arial Black and Times New Roman, respectively. Brown-menu idle ink uses the original 45% white opacity. Comparing the original OPTIONS lettering in frames 0 and 4 recovers its mixture of intact paint and occasional worn areas; `ui/plank_lettering.gdshader` applies this ink wear to SHOP and restores it through frame 4. Yellow serif lettering keeps its original dark-ink appearance without the white-paint wear effect.

Frames 0..4 keep the smaller lettering; frame 5 enlarges it, and frame 6 moves the complete board down four pixels. The wood and text belong to the same `PlankBody` control and inherit a single transform, so the lettering cannot remain stationary while its board moves. Row 3 of the original atlas supplies the exposed fence around the moving plank. The text child ignores mouse input, so it does not intercept menu clicks.

The yellow submenu maps original rows 0, 1, 3, 4, then the new Back row; the Duelist LV strip is not drawn. `tests/test_title_menu.gd` checks navigation and GPU-rendered artwork: original wood colors, continuity across the former inset, intact/worn ink balance, and exact pixel equality of the whole board and text before/after the four-pixel hover shift. It saves all seven frames for visual inspection.

The options gear dispatches the existing `options` action. The game shell still has no Options screen implementation. Replay and 2-player functionality are unchanged; this change only reorganizes their menu positions.

Generation prompt:

Production sprite asset extraction/edit for an existing 2004 PC game. Preserve the EXACT simple original horizontal wood-grain plank style shown in references. Output one transparent 1536x1024 asset sheet with THREE clearly separated assets, NO labels and NO text. TOP region y=100..300: one blank brown/orange wooden menu plank taken from reference1, front-facing long flat rectangular board, approximately 1280 pixels wide and 140 pixels tall (same 400:44 proportion as original), dense fine straight horizontal wood grain, thin dark brown top/bottom bevel, slightly irregular cut edges, NO writing. MIDDLE region y=430..630: one blank pale golden-yellow wooden menu plank taken from reference2, exactly same length and proportions, dense straight horizontal grain and simple thin yellow edge, no writing, NO Duelist LV metal bar. BOTTOM region y=750..1000: one small standalone eight-toothed OPTIONS gear icon: pale brushed silver metal with charcoal outline and dark central circular hole, simple readable silhouette, slight bevel matching the silver logo plate in a retro PC game, about 180x180 centered. True alpha transparency everywhere outside these three sprites including gear's hole. Do not show any chainlink fence or other background between sprites. No labels, no shadows outside sprites, no screws on planks, no ornate frames, no perspective, no dramatic lighting, no new visual theme, do not create a UI mockup. Keep the original game wood strip materials and minimal flat rendering. The plank labels will be drawn in-game, so both wooden planks must be COMPLETELY BLANK.
